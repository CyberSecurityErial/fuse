# QKV Projection + A2A Benchmark

## 口径

- BF16 QKV projection 后执行完整 Q/K/V Ulysses A2A；
- 三个人工压力shape加五组真实GQA模型，六档全局序列长度，CP4/CP8，共96个setting；
- `M=B×S/CP`、`N=(Hq+2Hkv)×D`、`K=hidden_size`；
- 每个正式结果使用10次warmup + 50次采样；MPI一进程一卡，每个样本先取
  跨rank最大延迟，再报告p50/p95；
- eager与CUDA Graph分别采样、分别成列，不拿两列之间的差值当算子收益；
- 主表不启用defer-V，融合与所有基线都搬完整Q/K/V；吞吐只计算`2MNK`。

### 测试设备

设备、卡组和软件口径与A2A+OProj一致：CP4固定使用 `0,2,4,5`，CP8使用全部GPU；CP8包含三张1500 MHz卡。`v5.0` 是不改热路径的启动口径基线，`v6.0` 增加QKV的wave-time tile选择。

## 基线如何调优

TE、经典cuBLAS和cuBLASLt分别完成QKV GEMM；随后同一完整Q/K/V pack+A2A。每个setting先扫描48个NCCL tuple，保留route top-3，再联合搜索Graph/eager、stream优先级、`pack_block={128,256,512,1024}`与`pack_warps={4,8}`。每个NCCL tuple使用独立进程组；正式winner统一10+50。cuBLASLt heuristic使用64 MiB workspace与5+30本地调优。

适配的TE Userbuffers基线搜索 `comm_sm={4,8,12,16,20,24}`，再检查3 streams、push/pull、CE/SM、pack参数、方向和local-first；top-3统一10+50。它使用TE Userbuffers原语，但不是TE发布包里的现成QKV融合算子。

TE Userbuffers 正式结果使用一进程一卡：每个 rank 的 CUDA event 覆盖全部 QKV
slab GEMM、send/recv 和最终 unpack，主 stream 在 stop 前显式等待通信 stream；随后
对各 rank elapsed time 做 `dist.MAX`。Graph capture 和额外 warmup replay 位于正式
采样之外，因此表内不包含首次 capture/upload 成本。

## v6 tile选择

v6保留 `M128N128`、`M128N160`、`M128N256 cluster-M2` 和
`M128N320 cluster-M2` 四种实现。运行时不逐shape搜索tile，只计算：

```text
score(policy) = persistent wave数 × 该policy的一整波实测时间
```

一整波时间来自纯CUTLASS compute-subgrid，在H200的132 SM上分别为
`comm_ctas=24/32`、`K={2048,3072,4096,5120,16384}` 标定；完整40行原始
p50保存在 [`qkv_wave_calibration.csv`](qkv_wave_calibration.csv)。实际`M/N`只决定
tile数和wave数，TE Userbuffers结果与逐case winner都不进入评分。K位于标定点之间时
做线性插值；设备不是132 SM、comm不为24/32、K越界或启用peer-interleaved时，回退
到v5策略。

默认无需设置环境变量。调试或消融时可以使用：

```bash
unset FUSE_QKV_GEMM_POLICY                 # v6默认选择器
export FUSE_QKV_GEMM_POLICY=legacy         # v5策略
export FUSE_QKV_GEMM_POLICY=m128n160       # 强制单一policy
export FUSE_QKV_GEMM_POLICY=wave_time_model
```

本次96点归档为避免环境含义不清，显式设置了`wave_time_model`，因此机器可读表中
`qkv_policy_request`为该值；它与v6未设置环境变量时的默认路径完全相同。

## 复现

```bash
export FUSE_CP4_DEVICES=0,2,4,5
export FUSE_CP8_DEVICES=0,1,2,3,4,5,6,7
unset FUSE_QKV_GEMM_POLICY
cmake -S . -B build -DCMAKE_BUILD_TYPE=Release
cmake --build build --parallel 8 --target qkvproj_a2a_mpi_bench

for phase in shape-table baseline-nccl-sweep baseline-mode-sweep baseline-formal baseline-aggregate fuse-mpi-formal fuse-mpi-aggregate comparison-table; do
  python3 'benchmarks/QKVproj+a2a/qkv_shape_bench.py' --phase "$phase"
done
python3 'benchmarks/QKVproj+a2a/te_userbuffers_shape_bench.py' --phase all
```

`fuse-mpi-formal`从 `mpi_config_manifest.csv`读取每个case的完整
`comm_ctas/raster/swizzle`，并各跑一次eager和Graph。Graph是一个预上传的
单次replay，内部含60个单调epoch节点；capture、instantiate、upload和MPI
barrier均不计时。旧 `fuse-formal`/`fuse-aggregate` 保留为单进程诊断入口，
不得写入正式性能表。

## 如何让使用者复现当前最佳结果

使用Release/SM90a构建、固定相同卡组，并保持`FUSE_QKV_GEMM_POLICY`未设置即可
复现v6默认tile选择。正式manifest只固定此前已经调好的`comm_ctas/raster/swizzle`；
tile由运行时模型选择，没有按96个shape保存winner。完整执行外部基线搜索与MPI
runner可复现对比表。短序列与大宽度仍有bad case，本文不把全部shape称为SOTA。
