# QKV Projection + A2A Benchmark

## 口径

- BF16 QKV projection 后执行完整 Q/K/V Ulysses A2A；
- 三个人工压力shape加五组真实GQA模型，六档全局序列长度，CP4/CP8，共96个setting；
- `M=B×S/CP`、`N=(Hq+2Hkv)×D`、`K=hidden_size`；
- 每个正式结果使用10次warmup + 50次采样，每次先取跨rank最大延迟，再报告p50/p95；
- 主表不启用defer-V，融合与所有基线都搬完整Q/K/V；吞吐只计算`2MNK`。

### 测试设备

设备、卡组和软件口径与A2A+OProj一致：CP4固定使用 `0,2,4,5`，CP8使用全部GPU；CP8包含三张1500 MHz卡。算子代码锚点为 `334f9d35dbd50caa06d0ff55c4067e19d132a710`。本轮只建立强benchmark，没有修改QKV算子优化逻辑。

## Shape

Q/K/V必须按真实head geometry分段，因此即使MNK相同，`Hq/Hkv/D`也属于benchmark合同。全局序列固定为1K/4K/16K/128K/256K/512K。

## 基线如何调优

TE、经典cuBLAS和cuBLASLt分别完成QKV GEMM；随后同一完整Q/K/V pack+A2A。每个setting先扫描48个NCCL tuple，保留route top-3，再联合搜索Graph/eager、stream优先级、`pack_block={128,256,512,1024}`与`pack_warps={4,8}`。每个NCCL tuple使用独立进程组；正式winner统一10+50。cuBLASLt heuristic使用64 MiB workspace与5+30本地调优。

适配的TE Userbuffers基线搜索 `comm_sm={4,8,12,16,20,24}`，再检查3 streams、push/pull、CE/SM、pack参数、方向和local-first；top-3统一10+50。它使用TE Userbuffers原语，但不是TE发布包里的现成QKV融合算子。

## 复现

```bash
export FUSE_CP4_DEVICES=0,2,4,5
export FUSE_CP8_DEVICES=0,1,2,3,4,5,6,7
for phase in shape-table baseline-nccl-sweep baseline-mode-sweep baseline-formal baseline-aggregate fuse-formal fuse-aggregate comparison-table; do
  python3 'benchmarks/QKVproj+a2a/qkv_shape_bench.py' --phase "$phase"
done
python3 'benchmarks/QKVproj+a2a/te_userbuffers_shape_bench.py' --phase all
```

## 如何让使用者复现当前最佳结果

当前QKV路径尚未做专项性能优化，正式表使用现有生产入口与运行时解析后的 `comm_ctas`，不对shape手工刷tile。使用Release/SM90a构建、固定相同卡组，并完整执行上面的外部基线搜索，才能复现当前对比。短序列和大宽度仍有明显bad case，本文不把当前实现称为SOTA。
