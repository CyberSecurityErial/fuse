# QKV Projection + A2A Benchmark

## 口径

- BF16 QKV projection 后执行完整 Q/K/V Ulysses A2A；
- 三个人工压力shape加五组真实GQA模型，六档全局序列长度，CP4/CP8，共96个setting；
- `M=B×S/CP`、`N=(Hq+2Hkv)×D`、`K=hidden_size`；
- 每个正式结果使用10次warmup + 50次采样；MPI一进程一卡，每个样本先取
  跨rank最大延迟，再报告p50/p95；
- eager与CUDA Graph分别采样、分别成列，不拿两列之间的差值当算子收益；
- 主表不启用defer-V，融合与所有基线都搬完整Q/K/V；吞吐只计算`2MNK`。

### 测试设备

设备、卡组和软件口径与A2A+OProj一致：CP4固定使用 `0,2,4,5`，CP8使用全部GPU；CP8包含三张1500 MHz卡。`v5.0`固化启动口径，`v6.0`加入wave-time tile选择，`v7.0`联合选择通信CTA与tile并缩短finalize尾部。

## 基线如何调优

TE、经典cuBLAS和cuBLASLt分别完成QKV GEMM；随后同一完整Q/K/V pack+A2A。每个setting先扫描48个NCCL tuple，保留route top-3，再联合搜索Graph/eager、stream优先级、`pack_block={128,256,512,1024}`与`pack_warps={4,8}`。每个NCCL tuple使用独立进程组；正式winner统一10+50。cuBLASLt heuristic使用64 MiB workspace与5+30本地调优。

适配的TE Userbuffers基线搜索 `comm_sm={4,8,12,16,20,24}`，再检查3 streams、push/pull、CE/SM、pack参数、方向和local-first；top-3统一10+50。它使用TE Userbuffers原语，但不是TE发布包里的现成QKV融合算子。

TE Userbuffers 正式结果使用一进程一卡：每个 rank 的 CUDA event 覆盖全部 QKV
slab GEMM、send/recv 和最终 unpack，主 stream 在 stop 前显式等待通信 stream；随后
对各 rank elapsed time 做 `dist.MAX`。Graph capture 和额外 warmup replay 位于正式
采样之外，因此表内不包含首次 capture/upload 成本。

## v7 联合流水策略

v7同时选择通信 CTA 和 GEMM tile。候选 tile 为 `M128N128`、`M128N160`、
`M128N192`、`M128N256 cluster-M2`、`M128N320 cluster-M2`；通信 CTA 在
`4..32` 的偶数中枚举。评分只使用启动前已经知道的量：M/N/K、CP、head geometry、
SM数、远端字节数、tile/cluster几何和H200原语成本。

```text
compute = persistent_waves × calibrated_wave_time(tile, K)
route   = max(16KiB_task_waves, remote_bytes / one_way_NVLink_rate)
score   = compute + max(one_task_wave, route - later_compute_waves)
```

`M/N`只决定work unit和wave数，K在相邻原语标定点间线性插值。通信侧按每个CTA
12个bulk slot计算task wave，单向NVLink按设备带宽和通信CTA饱和度给出下界。若
cluster-M2与cluster-M1需要相同wave数，且cluster-M1至多多花两个route service
quantum，优先保留CTA独立前进，避免通信竞争把两个compute CTA绑成一个前进单元。

整波GEMM标定保存在 [`qkv_wave_calibration.csv`](qkv_wave_calibration.csv)。N192
使用 `M=128,N=20736` 的一整波测量；它在H200上为168 registers/thread、0 spill、
222208 B dynamic SMEM。route service quantum来自同一CP4/c6 route-only测试：64个
16 KiB task为14.736 μs，128个task为19.008 μs，增量取4.3 μs。TE Userbuffers
结果、模型名称和96点winner都不进入运行时选择。

finalize也改为第一warp的8个lane并行发布、并行等待8个source epoch；system fence、
epoch语义和kernel退出条件保持不变。默认路径无需环境变量。回退或消融使用：

```bash
unset FUSE_QKV_COMM_POLICY FUSE_QKV_GEMM_POLICY  # v7默认
export FUSE_QKV_COMM_POLICY=legacy               # v6通信/tile选择域
export FUSE_QKV_GEMM_POLICY=legacy               # 再回退到v5 tile
export FUSE_QKV_GEMM_POLICY=m128n192             # 固定单一tile
```

标定域以外的设备、K、head dim或peer-interleaved布局会走成熟回退路径，不外推当前
H200模型。

## 复现

```bash
export FUSE_CP4_DEVICES=0,2,4,5
export FUSE_CP8_DEVICES=0,1,2,3,4,5,6,7
unset FUSE_QKV_COMM_POLICY FUSE_QKV_GEMM_POLICY
cmake -S . -B build -DCMAKE_BUILD_TYPE=Release
cmake --build build --parallel 8 --target qkvproj_a2a_mpi_bench

for phase in shape-table baseline-nccl-sweep baseline-mode-sweep baseline-formal baseline-aggregate fuse-mpi-formal fuse-mpi-aggregate comparison-table; do
  python3 'benchmarks/QKVproj+a2a/qkv_shape_bench.py' --phase "$phase"
done
python3 'benchmarks/QKVproj+a2a/te_userbuffers_shape_bench.py' --phase all
```

`fuse-mpi-formal`默认对全部case固定 `comm_ctas=0/raster=n/swizzle=1`，由运行时
统一模型选择通信CTA和tile，不读取逐case配置。Graph是一个预上传的单次replay，
内部含60个单调epoch节点；capture、instantiate、upload和MPI barrier均不计时。
`--no-mpi-auto-comm`与 `mpi_config_manifest.csv`只用于复现v5/v6历史数据。旧
`fuse-formal`/`fuse-aggregate`保留为单进程诊断入口，不得写入正式性能表。

## 如何让使用者复现当前最佳结果

使用Release/SM90a构建、固定相同卡组，并保持两个QKV policy环境变量未设置即可
复现v7默认路径。96点使用同一 `comm_ctas=0/raster=n/swizzle=1` 入口，没有按shape
保存通信或tile winner。完整执行外部基线搜索与MPI runner可复现对比表。
