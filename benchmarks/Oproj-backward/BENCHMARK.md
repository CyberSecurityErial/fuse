# Output Projection Backward Benchmark

## 口径

- BF16 output projection 反向，分别测数据梯度阶段 B 和权重梯度阶段 W；
- B 阶段先计算完整 head 宽度的 attention 梯度，再执行 Ulysses Sequence→Head A2A；
- W 阶段使用 `dY` 和前向 attention 输出计算 `dWo`；
- 三个人工压力 shape 加五组真实 GQA 模型，六档全局序列长度，CP4/CP8，共 96 个 setting；
- 每个正式结果使用 10 次 warmup + 50 次采样；MPI 一进程一卡，每个样本先取跨 rank 最大延迟，再报告 p50/p95；
- Eager 与 CUDA Graph 分别采样、分别成列；Graph 的 capture、instantiate、upload 和 host launch 不计时；
- 吞吐同时计算 B 和 W 的 GEMM FLOPs，即总计 `4×M×hidden×attention_width`。
- 经典 cuBLAS 使用相同的 B/W MNK 和真实零拷贝转置视图，分别测纯 GEMM；普通模式的 W 对照使用 `beta=0`，ZeroBubble 使用 `beta=1`，保证累加语义相同。它不包含 A2A，用来表示该 shape 在当前卡组上的计算上限。
- 每份 raw JSON 直接保存 B/W MNK、自动请求、最终通信 CTA、tile、beta 和 50 个 max-rank 样本；汇总表不靠模型名反推反向矩阵。

### 测试设备

CP4 固定使用物理卡 `0,2,4,5`，CP8 使用全部 8 张 132-SM H200 级 GPU。物理卡 `1,3,6` 的 SM 频率上限为 1500 MHz，其余为 1980 MHz；显存频率均为 3201 MHz。经典 cuBLAS 在本轮同一卡组上同步测量；“前向占比”使用仓库已发布的同 shape、同启动方式前向 Golden，作为统一的版本目标，不冒充同一时刻的成对 A/B。

## 反向 Shape 和顺序

令 `A=Hq×D`。训练框架按线性层常规格式把前向权重保存为 `[H,A]`（输出维在前）；反向 B 直接读取这块存储，不在运行时转置或复制。两个反向 GEMM 是：

```text
B: dA[M,A]    = dY[M,H] × stored_Wo[H,A]
   GEMM MNK    = M × A × H

W: dWo[H,A]   = dYᵀ[H,M] × saved_A[M,A]
   GEMM MNK    = H × A × M
```

这里 `M=B×S/CP`。前向顺序是 A2A→OProj，反向自然变为 OProj dgrad→A2A：GEMM CTA 逐块生成 `dA`，通信 CTA 在对应块 ready 后直接把目标 head 切片写到各个 peer 的最终 attention-gradient 布局。框架不需要在两个阶段之间插入独立重排 kernel。

|---|---|---|---|---|
| artificial | 代表小型 | `M×4096×4096` | `4096×4096×M` | 32/128 |
| artificial | 代表中型 | `M×5120×5120` | `5120×5120×M` | 40/128 |
| artificial | 代表大型 | `M×16384×7168` | `7168×16384×M` | 128/128 |
| model | 生产 Qwen Dense | `M×2048×2048` | `2048×2048×M` | 16/128 |
| model | Nanbeige4.2-3B | `M×6144×3072` | `3072×6144×M` | 48/128 |
| model | Llama-3-8B | `M×4096×4096` | `4096×4096×M` | 32/128 |
| model | Qwen2.5-14B/32B | `M×5120×5120` | `5120×5120×M` | 40/128 |
| model | Llama-3.1-405B | `M×16384×16384` | `16384×16384×M` | 128/128 |

## 普通反向和 ZeroBubble

普通模式调用 `launch_oproj_backward()`，在同一 stream 中严格执行 B→W。ZeroBubble 模式先调用 `launch_oproj_backward_data()`，以后再调用 `launch_oproj_backward_weight()`。

分离期间必须保留 `dY` 和前向 attention 输出 `saved_A`。它们已经是 Wgrad 直接需要的矩阵，不要求额外 layout transform；如果框架不能延长原张量寿命，就必须保存一份，这个存储成本不能由算子凭空消除。每个尚未完成的 B→W 间隔需要独立 slot。

正式 ZeroBubble 表使用 `beta=1`，把本次 `dWo` 累加到已经存在的 BF16 `main_grad`；普通同流表使用 `beta=0`。多个 W 阶段不能并发写同一个梯度地址。

## 自动策略

B 阶段统一传 `comm_ctas=0` 和 `gemm_policy=auto`。策略根据 M/N/K、CP、head 数、route task 数和可用 SM 联合选择通信 CTA 与 `M128N64/N128/N160/N192/N256`，不读取模型名或逐 case winner。第一次解析出的整数启动计划会在相同设备和 shape 的后续 Eager 调用中复用；动态地址与 epoch 不进入缓存。

W 阶段是独立的 CUTLASS Wgrad GEMM。普通模式把它紧接在 B 后面；ZeroBubble 只改变调度时间和 `main_grad` 累加语义，不改变矩阵公式。

正式 Graph 数据把 10 个预热 epoch 和 50 个正式 epoch 捕获成一条单调链，只 replay 一次。框架若要重复 replay 同一个 graph，必须统一重置跨卡状态，或更新 graph 中的 epoch，不能直接沿用上一次的 ready/done 值。

## 正确性门槛

- 小矩阵 smoke 覆盖 CP4/CP8、rank-major/causal 布局、普通 B→W、分离 B/W 和 `beta=1`，全部与独立 CPU 参考逐元素比较；
- 另有 CP4、batch=2、M=256 的 causal 用例，实际走 TMA 路径，验证 batch 偏移和双 chunk 映射；
- 正式 S=1K 检查跨 rank ready/done 协议、全部 route 输出、`dA`、`dWo` 均被执行；
- 原有前向 QKV/OProj 完整 smoke 继续通过；v9 的全部旧 device kernel 指令体在 v10 构建中保持不变。

## 复现

```bash
cmake -S . -B build-v10-release \
  -DCMAKE_BUILD_TYPE=Release -DFUSE_ENABLE_PROFILING=OFF
cmake --build build-v10-release --parallel 8 \
  --target backward_smoke backward_mpi_bench backward_cublas_mpi_bench

CUDA_VISIBLE_DEVICES=0,1,2,3,4,5,6,7 ./build-v10-release/backward_smoke

python3 benchmarks/backward/backward_shape_bench.py \
  --phase formal --phase cublas --phase aggregate \
  --operators oproj --launches eager,graph \
  --weight-modes deferred,immediate \
  --seqs 1024,4096,16384,131072,262144,524288 \
  --cps 4,8 --warmup 10 --iterations 50 \
  --bench build-v10-release/backward_mpi_bench \
  --cublas-bench build-v10-release/backward_cublas_mpi_bench \
  --results results/Oproj-backward/oproj_backward_shape_bench \
  --no-resume
```

runner 默认一次 MPI 启动完成四种组合，每种组合仍使用独立缓冲区、独立 10+50 和独立 JSON。若只测单一组合，可直接调用 `backward_mpi_bench --operator oproj --weight-mode ... --launch ...`。
